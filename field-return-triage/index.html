Field Return Triage · independent project

A returned part can pass the standard test and still have a fault. I built a tool that finds failure clues in the complaint, checks the exact words behind them, and suggests what a technician could test next.

Before taking this further

Public data, different setting
US vehicle complaints stand in for return reports. They do not contain a lab’s test history or represent one supplier’s parts.
Labels are imperfect
Component and safety fields come from a public coding process, not an engineer’s finding. Scores inherit that uncertainty.
Test suggestions are examples
A lab needs its own test catalogue, inspection points and escalation rules. A suggested test is not a confirmed diagnosis.
Agreement is not accuracy
Conditions such as moisture or vibration have no ground-truth labels here. Their score measures agreement with a fixed keyword rule.

This is a measured portfolio project. It has no production queue, authentication or validated deployment in a returns lab.

A traceable next step

Which returned parts need a closer look, and which test should run first? The flow keeps the original complaint attached to every suggestion.

  1. AI extraction

    Find the clues

    Read the complaint for symptoms, conditions and safety indications. Return a quote for each clue.

  2. Code

    Check the words

    Drop any clue whose quote does not appear in the original complaint.

  3. Hard rules

    Put safety first

    Safety goes to priority 1 with human review. Unclear cases go to human reading.

  4. Search + rulebook

    Suggest the test

    Find similar past cases. Map the checked clues to tests, inspections and questions.

  5. Technician

    Make the decision

    Accept the suggestion or change it with a reason. The real pipeline logs this feedback.

Adapt the domain knowledge

The component taxonomy and test rulebook are configurable. A lab would supply its own parts, complaint records and actual tests. The code still checks quotes, enforces safety rules and requires a person’s decision.

The separate trend path uses weekly counts and a statistical spike rule, without calling an AI model.

## Licence evidence, as retrieved on 2026-10-31

NHTSA's site policy, section *Ownership*
(<https://www.nhtsa.gov/about-nhtsa/privacy-policy>):

> "Information presented on this web site is considered public information and may be
> distributed or copied."

The data.gov catalogue metadata for both datasets names
`license = http://www.usa.gov/publicdomain/label/1.0/` and `accessLevel = public`; the
older catalogue page states it in words:

> "Public: This dataset is intended for public access and use. License: us-pd"

The public-domain label page defines the scope and the caveat
(<https://www.usa.gov/government-copyright>):

> "Government work is something created by a U.S. government officer or employee as part
> of their official duties."

> "On federal websites, other people may have rights to the work itself or how people use
> it. This includes publicity or privacy rights under state law."

**Conclusion.** Both datasets are U.S. Government works in the public domain, and derived
extracts may be redistributed. The privacy sentence is the reason for the hard rule in
`PLAN.md` section 5, not a redistribution restriction: the complaints contain personal
data contributed by the public, so identity and location columns are dropped and a
narrative that matches the PII screen is discarded, never committed.

## What this project commits from the datasets

- `data/library.jsonl.gz` — 20,000 past cases from complaints received 2020-2024.
- `data/eval.jsonl` — 400 evaluation complaints received 2025-2026, `frt` half.
- `data/trend/weekly.csv.gz` — weekly counts per make, model, model year and group.
- `data/trend/recalls.csv` — recall rows whose component maps to a group.
- `data/STATS.md` and `data/CHECKSUMS.txt` — the derivation record and file hashes.

The raw downloads are never committed (`data/raw/` is gitignored). The copied normative
files `data/nhtsa-spec.toml` and `data/groups.toml` are part of this licence record.

Identity and location columns (`CITY`, `STATE`, `VIN`, `STATE_OF_INCIDENT`,
`VEHICLE_OPERATOR`, `DEALER_NAME`, `DEALER_TEL`, `DEALER_CITY`, `DEALER_STATE`,
`DEALER_ZIP`) are dropped from every derived file. The committed data is a set of public
complaints, not return reports, and is used as a stand-in for a lab's own complaint text.
