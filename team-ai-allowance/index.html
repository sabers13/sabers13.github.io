Stop runaway AI coding loops.

I built a team policy console, background spend watcher, and in-terminal request tool on top of open-source LiteLLM so every engineer gets a clear weekly AI allowance and forgotten night or weekend loops pause automatically.

When a small engineering team shares one raw API key across Claude Code, OpenCode, and Codex, a single stuck retry loop on Friday evening can quietly burn the month’s budget. Here, each engineer works on a virtual key with an 80% soft warning, a 5% grace buffer, and one-command top-up requests from the terminal.

What I built

Open-source LiteLLM v1.105.1 enforces per-key hard budgets, but its built-in per-user management screens and approval workflows sit behind the enterprise license. I built the missing team layer using only open-source endpoints.

TypeScript Node.js 24 LiteLLM MCP PostgreSQL Playwright

  • Manager & member web console Server-rendered console on port 18080 with Overview, Member detail, Requests queue, Usage breakdown, Audit log, and CSV/JSON export.
  • Background spend & off-hours watcher Polls spend every 30 seconds, fires 80% soft warnings, blocks keys outside working hours once off-hours caps cross, and expires temporary grants.
  • In-terminal MCP & CLI request tools Engineers check remaining allowance (allowance_status), ask for more budget (allowance_request_more), or check approval status without leaving their editor.
  • OpenCode unattended loop guard Local plugin pauses a session after 30 minutes (40 calls at one call every 45 seconds) without a fresh human message.

What went wrong: streaming USD 0 rows

The most valuable result of running a real multi-agent team through the proxy was catching a metering failure that unit tests missed. Out of 369 gateway spend rows in LiteLLM_SpendLogs, 317 rows recorded USD 0 cost even though they carried 12,896,452 tokens.

Why it happened: Interactive CLI sessions use server-sent event (SSE) streaming against deepseek-v4.1-flash via an OpenAI-compatible upstream. When the upstream stream omitted final usage-cost metadata matching the custom model price map, LiteLLM v1.105.1 wrote the token counts to Postgres with spend = 0. Non-streaming calls priced accurately, which is why Mira’s hard limit (USD 0.056181) and the 18 / 18 live CLI checks triggered as designed, whereas Bo’s Night off-hours cap did not trip during streamed turns (leaving 5 of 7 scripted probes passing).

317 of 369 rows

Recorded USD 0 cost while carrying 12,896,452 streamed tokens during the 4-agent team test. Disclosed in full so anyone adopting open-source LiteLLM with custom OpenAI-compatible streaming endpoints knows to verify stream usage accounting (stream_options: {"include_usage": true}).

How the architecture works

Budget enforcement happens on the team gateway rather than trusting the developer’s laptop, while local CLI helpers and MCP tools keep requests fast inside the terminal.

1. On the member machine

Claude Code, OpenCode, or Codex points at the gateway on 127.0.0.1:14000 using a member virtual key stored with 0600 permissions. The local MCP server exposes allowance_status and allowance_request_more, and the OpenCode plugin pauses unattended loops after 30 minutes.

→
2. On the team server

Open-source LiteLLM v1.105.1 and PostgreSQL (127.0.0.1:15432) enforce hard budgets and model allowlists on every call. The Team AI Allowance service (127.0.0.1:18080) runs a 30-second watcher for 80% soft alerts, off-hours caps, and grant expiry.

→
3. For the manager

Managers review requests in the web console, approve full or partial top-ups with an expiration time, or deny with a written reason. Alerts deliver to local SMTP (127.0.0.1:18025) and webhook (127.0.0.1:18090) endpoints.

Why local edits cannot bypass a cap

Even if an engineer disables the local OpenCode plugin or edits local config files, the virtual key’s hard budget and model allowlist live on the LiteLLM gateway and Postgres database.

30-second watcher polling

Hard budget caps block inline on the next gateway call, while off-hours caps and 80% soft warnings evaluate on the 30-second watcher tick.

Single-host Docker stack

Designed for a small engineering team running on a single Linux/macOS host with loopback-bound ports rather than multi-region federation.

Open-source LiteLLM boundary

Uses only open-source LiteLLM proxy key routes and Postgres spend tables, with zero dependency on enterprise-licensed modules.

Local setup & verification

The stack runs on Node.js 24 and Docker Compose, binding all five services to 127.0.0.1 by default: console on 18080, LiteLLM gateway on 14000, PostgreSQL on 15432, mail catcher on 18025, and webhook catcher on 18090.

LiteLLM boundary & 9 limits

Team AI Allowance uses only open-source LiteLLM proxy routes (/key/generate, /key/update, /key/info, /key/block, /key/unblock) and its Postgres spend tables. Nine operational boundaries are documented:

Nine documented operational boundaries in v1.0.0
Boundary Behavior in v1.0.0 Operational impact
1. Streaming USD 0 cost rows 317 of 369 team-test rows logged USD 0 across 12,896,452 streamed tokens Upstream OpenAI-compatible streams must emit usage chunks or use token-count fallback pricing
2. Watcher poll interval Off-hours caps and 80% warnings evaluate every 30 seconds A burst of calls inside one 30-second window can briefly overshoot an off-hours threshold
3. Unattended plugin scope Client-side inactivity pause ships as an OpenCode plugin Claude Code and Codex rely on gateway hard budgets and off-hours caps unless wrapped
4. Client-side plugin trust The unattended pause runs on the member workstation Treated as a convenience brake; hard financial enforcement stays on the server
5. Shared team timezone Working hours are configured per team (e.g. Europe/Berlin) Distributed teams across continents should group members into regional teams
6. Passphrase session auth Console uses role passphrases and HTTP-only session cookies Built for internal VPN/SSH access rather than public internet exposure without SSO
7. In-flight call completion Budget checks happen before a model call starts A large single call that starts at 99% budget completes into the 5% grace buffer
8. Single-node Postgres State lives in one local PostgreSQL container Requires standard volume backups for production durability
9. Custom model price table Non-standard model IDs need explicit input/output token rates in LiteLLM config Unmapped models default to zero cost unless added to the gateway model list
